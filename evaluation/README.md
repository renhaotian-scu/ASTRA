# Segmentation-to-box target-level evaluation

This CPU evaluator exposes the four-metric WP2-v2 protocol used for the additional segmentation-method comparison: **P (%), Pd/Recall (%), F1 (%), and Fa (false-positive instances per image)**. It consumes probability maps and the same bounding-box GT used for detection evaluation. It does not run a model, train, calculate AP, or reproduce paper results without the corresponding predictions and split assets.

The numerical conversion, matching, and threshold tie rules are extracted from the recorded evaluation functions. Original file SHA256 values, function line ranges, and function fingerprints are in [SOURCE_PROVENANCE.json](SOURCE_PROVENANCE.json). The portable file format and CLI are new wrappers; they do not change those numerical functions.

## Exact protocol

1. Accept finite probabilities in `[0,1]`, convert to float32, and restore to the original image dimensions using the recorded Pillow bilinear operation if necessary. Inputs must already have letterbox padding removed. No sigmoid, normalization, automatic crop, or guessed padding is applied.
2. Threshold by `probability >= mask_threshold`. Select the threshold on **validation only** from `(0.1, 0.2, 0.3, 0.5, 0.7, 0.9)`.
3. Extract **eight-connected** foreground components. Retain every component, including a single pixel. Use tight raster-support `xywh` boxes: width and height are `max-min+1`. Apply only the dataset's previously fixed annotation-coordinate offset from the manifest.
4. Use every component box: **no morphology, minimum-area filtering, NMS, manual splitting/merging, top-K, or second confidence threshold**.
5. Preserve the original evaluator's matching order: descending **mean of the original restored probabilities over the actual foreground pixels in each component**. This is not the mean over the box, a maximum, or an invented constant confidence. The component mean is retained for the existing matching order; no additional instance-scoring method or AP ranking protocol is introduced. All components count irrespective of their ordering value.
6. Perform the recorded **score-ordered greedy, one-to-one IoU ≥ 0.5 matching** independently per image. Do not replace it with Hungarian/maximum-cardinality assignment. Equal prediction scores retain input order; connected components initially follow the labeling enumeration. When two unused GT boxes have exactly equal IoU, the later GT annotation wins, matching the original `>=` update. Keep the supplied GT annotation order.
7. Select the validation candidate with the largest box F1. Within tolerance `1e-12`, choose lower validation Fa, then the lower mask threshold. Freeze that choice before test evaluation. The CLI provides no test-threshold search.

For the aggregate counts across all images:

```text
P  = 100 * TP / (TP + FP)
Pd = R = 100 * TP / (TP + FN)
F1 = 200 * (P/100) * (R/100) / ((P+R)/100)
Fa = FP / number_of_all_images
```

Undefined divisions return zero, as in the recorded code. Empty-GT images remain in the Fa denominator, and detections on them count as false positives. `metrics.json` uses the original `R` key; it is exactly Pd under this matching rule. This is target-level Fa in `img^-1`, not pixel-level Fa. The original GT helper excludes `iscrowd` annotations from ordinary GT matching; the intended benchmark annotations are non-crowd.

ASTRA's native detector working point remains its own validation-selected query confidence. Do not pass every native detector query as a detection through this segmentation converter.

## Install and run

From the repository root, with Python 3.8 or later:

```bash
python -m pip install -r evaluation/requirements.txt
python -m evaluation describe
python -m evaluation select --manifest data/manifest.json --probabilities data/probabilities.json --output results/validation
python -m evaluation test --manifest data/manifest.json --probabilities data/probabilities.json --selection results/validation/selection.json --output results/test
```

Use a new or empty output directory. Existing records are not overwritten. `select` writes the six validation candidates, protocol, and an integrity-checked `selection.json`. It loads only validation probability maps; test GT file bytes are hashed to bind the split identity, without using test labels for selection. `test` verifies the manifest/GT identities, frozen selection, protocol, and declared prediction-set identity. It writes all component boxes, per-image matching details, and aggregate counts/metrics.

The optional checkpoint SHA256 and prediction-set ID record user-supplied provenance. The evaluator cannot independently prove that external arrays were generated by that checkpoint. Model-specific inference and preprocessing adapters must provide that provenance separately.

## Portable input files

All paths are relative to their containing JSON file and stay within that directory. This avoids shipping machine-specific paths. Use the exact benchmark split lists and supplied GT files for an actual comparison; this package does not create or revise dataset splits.

`manifest.json` contains validation/test sample identities, original dimensions, and GT locations. Image IDs may repeat across splits; sample IDs must be unique. Every GT image, including negative images, needs one sample entry.

```json
{
  "version": 1,
  "categories": [{"id": 0, "name": "target"}],
  "mask_box_xy_offset": [0, 0],
  "samples": [
    {"sample_id": "example:val-a", "split": "val", "image_id": 1, "height": 256, "width": 256},
    {"sample_id": "example:test-a", "split": "test", "image_id": 1, "height": 256, "width": 256}
  ],
  "splits": {
    "val": {"gt_json": "gt_val.json"},
    "test": {"gt_json": "gt_test.json"}
  }
}
```

The two GT JSON files use COCO-style `images`, `categories`, and `annotations` with positive-extent `xywh` boxes and a single target category. Original `width`/`height` values must match the manifest. The category ID is read from GT, including ID zero. The box offset is a dataset annotation convention fixed before evaluation; it is not a tunable test parameter.

`probabilities.json` explicitly maps sample IDs to numeric `.npy` arrays. Save probabilities before image encoding or quantization; PNG/JPEG masks and raw logits are not accepted. A map may contain singleton batch/channel axes supported by the recorded restoration helper. Any resize is bilinear to the original dimensions; **model-specific letterbox padding must be undone before export**. Set `probability_space` to `unpadded` only after doing so.

```json
{
  "prediction_set_id": "one-model-one-checkpoint",
  "probability_space": "unpadded",
  "splits": {
    "val": [{"sample_id": "example:val-a", "path": "maps/val-a.npy"}],
    "test": [{"sample_id": "example:test-a", "path": "maps/test-a.npy"}]
  }
}
```

An optional top-level `checkpoint_sha256` is a lowercase 64-character SHA256 string. An optional per-map `sha256` is checked when supplied. The CLI records actual map hashes. Validation and test must declare the same prediction-set ID and checkpoint identity. Missing, duplicate, and foreign sample entries are rejected. Selection may receive a validation-only probability index.

Keep the manifest and GT files unchanged after freezing. Their SHA256 fingerprints bind the test operation to that selection; formatting changes to these JSON files also change the identity. Do not hand-edit a frozen threshold or use test results to select it.

## Synthetic demonstration and tests

```bash
python -m evaluation.make_synthetic_example --output demo
python -m evaluation select --manifest demo/manifest.json --probabilities demo/probabilities.json --output demo_selected
python -m evaluation test --manifest demo/manifest.json --probabilities demo/probabilities.json --selection demo_selected/selection.json --output demo_test
python -m unittest discover -s tests -p test_segmentation_evaluation.py -v
```

The toy validation fixture selects `0.3`. Its fixed-threshold test has `TP=1, FP=1, FN=0`, `P=50%`, `Pd=100%`, `F1=66.666...%`, and `Fa=0.5 img^-1`. **These are synthetic hand-checkable protocol fixtures, not paper or benchmark scores.**

Tests use standard-library `unittest` and the evaluation dependencies; no extra test package is needed. They lock eight-connectivity, tight boxes, single-pixel retention, more than 300 components, foreground-mean ordering, the greedy/optimal-assignment distinction, tie behavior, empty-image accounting, exact split coverage, frozen selection, and CLI outputs. Per-function source-text fingerprints also check that the extracted numerical functions retain their recorded bodies; line endings are normalized to LF. They do not validate real-model accuracy, private dataset identity, or unpublished benchmark results.
